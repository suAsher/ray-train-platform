# 团队目录协作读写

本次变更将新建训练和调试容器的 `/mnt/storage/team` 开放为当前团队成员共同读写，包含普通成员、团队管理员和超级管理员。跨团队隔离保持原有规则；选择团队来自当前有效成员关系，而不是用户填写路径。

## 使用方式

建议每个项目创建独立子目录，再按产物用途及版本组织，避免多人覆盖同名文件：

```text
/mnt/storage/team/<项目名>/<产物名>/<版本>/
```

团队内其他成员在同一团队挂载下使用该路径。目录中的内容可以被团队成员修改、覆盖和删除，版本目录名本身不构成不可变保证。写入完成并确认文件可读后再通知使用者，不以目录已出现代替文件全部写完。

## 权限边界

| 入口或目录 | 本次规则 |
| --- | --- |
| 容器内 `/mnt/storage/team` | 当前团队全员读写 |
| 容器内 `/mnt/storage/public` | 所有角色仍只读 |
| 容器内 IDC 数据目录 | 仍只读 |
| 任务输入别名 `PLATFORM_DATASET_PATH` | 保留只读挂载；若来源是 team，团队路径仍可用于修改同一份数据，因此不再具备内容不可变保证 |
| 普通成员网页上传到 team/public | 仍拒绝；容器权限不授予网页管理写权限 |
| 既有管理员数据同步 | 保持原授权规则 |

本次不包含普通成员的平台同步按钮、审批或共享产物版本管理。

## 生效范围

新调试环境创建时采用新的团队目录权限。新训练提交时保存可写团队根；已提交任务保留原快照，旧任务重试/恢复不能自动改写权限。

已经运行的调试环境不会被停止、重建或修改。若原环境仍只读，可在本人结束当前工作后正常停止，再创建新环境。新建任务若团队存储尚未准备好，应按页面提示等待，不借用其他团队卷或将旧只读卷伪装为可写。

## 实现说明

使用已经存在的可写 tenant-root PVC，以受限 subPath 暴露本团队 shared 目录；不修改既有 shared binding、PV 挂载选项或用户文件。公共和 IDC 的容器挂载继续强制只读。

持久化任务合同同时接受旧只读团队根和新可写团队根，渲染器尊重每个快照的权限；同一个 PVC 的多个子目录共享卷来源，但每个挂载仍有各自的读写标记。

回退后端不能自动收回已经创建的可写环境权限；有需要时应另行安排用户结束并重新创建环境，不能为了回退强制中断训练。
