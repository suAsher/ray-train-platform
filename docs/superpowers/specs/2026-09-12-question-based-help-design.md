# 使用说明：按问题查找、按单篇阅读

状态：已实现、发布并完成登录浏览器验收；版本、证据及 Portal Pod 摘要未独立核实的限制记录在 [Help 内容覆盖矩阵](../../HELP_CONTENT_COVERAGE_20260912.md)。设计依据为七篇聚合文档与 37 篇源记录（34 篇用户文档、三篇管理员文档）。

## 目标与判断

一级分类控制导航复杂度，问题标题帮助用户识别内容，独立文章承载完整步骤。一篇文章解决一类明确问题，并有可复制的独立链接。文章数量随问题增长，不再把“文章少”作为设计目标。

当前七篇长文恢复了内容，但训练篇有 56 个小节，重复“开始前、成功标志、失败处理”的目录缺乏上下文。因此改成六个可折叠分类、独立问题文档；用户正文完整保留，首页提供常见问题入口。

## 页面与交互

- 首页：标题“使用说明”、全站问题搜索、三个新手入口（安装 CLI、准备代码与数据、提交第一条任务）、人工编辑的常见问题列表。不显示没有统计依据的“热门”或浏览量。
- 左侧目录：六个分类默认收起；打开文章时自动展开所属分类并高亮问题标题。分类页显示全部问题和一句摘要。目录仅两级，文章内标题不加入左侧树。
- 阅读页：面包屑 → 问题标题 → 直接结论 → 完整操作步骤 → 验证方法 → 失败分支 → 相关问题。右侧只显示当前文章的小节；窄屏折叠为“本篇目录”。不在正文前放一整块新手流程。
- 搜索：搜索标题、别名、错误码、命令和全文；标题/错误码准确命中优先。结果显示“具体问题标题、所属分类、命中片段”，打开对应文章并定位命中小节。输入 `413` 应首先看到上传问题；输入 `run_id` 应看到 ID 关联与 MLflow 查询文档。
- 状态：无结果时保留输入并建议相关分类；文档加载失败支持重试；不存在/下架显示明确状态，不能默默回到第一篇。
- 文章动作：复制本文链接、复制代码、下载本文。下载整套说明放在首页次要位置；文章底部提供相关问题，不要求按固定顺序读完全部文档。
- 管理端：普通阅读不出现管理员文章；具备权限的编辑入口放在平台管理中。管理员可继续编辑原始文章和查看历史。

## 内容写法

首屏先回答问题。例如“任务排队”先说明配额与可放置资源共同决定启动，然后依次给出查看配额、查看队列原因、核对 Worker 规模、联系支持的条件。每一步写操作位置和预期结果。

不用为每篇文章机械补齐相同模板。操作类以步骤和验证为主；故障类以现象、判断、解决为主；API 类直接给地址、认证、请求与响应。复杂参数和完整命令保留在文章内，不能用一行摘要或“联系管理员”替代现有答案。

MLflow 查询与写入两篇互相链接。Model Registry 的已有方法可放在写入文章对应小节；未完成的评估审批或 Serving 流程明确标为尚不可用，不写成已经可照做的指南。

## 实现范围与兼容

- Portal：Help 首页、折叠目录、单篇阅读、搜索结果、文章链接/下载。沿用安全 Markdown 和代码复制组件。
- 后端：为新版帮助增加独立文章目录/读取视图，旧七篇聚合接口继续兼容旧前端；不让新版依赖 `/admin/help/documents`。文章 ID、目录节点 ID 分开。
- 保留已发布文章 ID 和历史。最近七主题链接映射到对应分类总览；其中与老文章同名的 `quickstart/debug/mlflow` 仍优先打开文章。最近 `#topic:section` 链接按稳定映射定位原文章；找不到旧小节时明确提示，不猜错文章。
- 原始源、人工修改、新汇总内容分别建立覆盖映射；不直接回填覆盖人工编辑，不删除或迁移用户文件。
- 管理员三篇仍不公开；未知自定义文章沿用原发布权限和正文，显示在其分类内，不自行另造一篇摘要。
- 不改 MLflow 鉴权、训练、配额、调度或运行时。

## 验收标准

1. 用户展开分类后，可以直接看到并打开每个具体问题，阅读区域只包含当前文章。
2. 34 篇用户源内容及近期有效补充全部有对应文章；原始管理记录与人工编辑不变，管理员文章不出现在搜索和导出中。
3. 搜索 `413`、`续训`、`run_id`、`缺少依赖`、`没有曲线` 均能返回具体问题，点击定位正确；返回列表后保留搜索词。
4. 从任务页/实验中心/旧书签打开文章正确；链接刷新、浏览器返回和前进可用。
5. 首页目录简洁，长文章侧栏与当前文章目录可访问；移动端不挤成三列。复制代码/本文链接/下载本文与整套导出可用。
6. 按 release 流程在构建机验证候选，通过后推送同步和发布；设计稿本身不改变线上行为。
