# GPU 占用明细设计

## 目标

让平台管理员准确回答“哪些 GPU 正被谁、哪个团队、哪类工作负载占用”，并消除集群物理已分配 GPU 与训练任务列表不一致时的认知盲区。

## 权限

- `SuperAdmin` 查看全平台训练任务和交互式调试环境。
- `TenantAdmin` 仅查看自己团队的训练任务和交互式调试环境。
- `Engineer` 不访问管理明细，继续只查看自己的任务与调试环境。
- 本期只提供查看能力；停止训练仍沿用原有操作，暂不增加管理员代用户停止调试环境，避免误杀交互会话。

## 数据模型与接口

新增只读接口 `GET /api/v1/gpu-allocations`，返回所有非终态 GPU 工作负载。每条记录包含：

- `id`、`type`（`TRAINING_JOB` 或 `DEBUG_WORKSPACE`）、`name`
- `tenantId`、`userId`、`username`
- `state`、`gpuCount`
- `namespace`、`resourceName`
- `createdAt`、可用时返回 `startedAt`

查询在服务端执行租户隔离，前端参数不能扩大权限范围。用户名从平台身份表批量映射；找不到时显示稳定的用户 ID，不能丢失占用记录。

## 页面

1. “集群算力概览”将原训练任务表改成“GPU 占用明细”，同时显示训练任务数、调试环境数与明细 GPU 总数。
2. “平台管理 → 队列与运行中”保留训练任务的 Kueue 管理表，新增调试环境明细表，避免改变已有停止训练操作。
3. 调试环境行展示用户、团队、GPU、状态、启动时间、持续时间、Namespace 与 RayCluster。

## 一致性与错误处理

- GPU 配额仍使用现有数据库事务统计，不改变提交和调度语义。
- 物理已分配来自 Kubernetes 拓扑；明细来自平台数据库。页面明确显示两者差值可能来自 RayCluster 释放窗口。
- 身份映射失败时接口仍返回占用记录；数据库查询失败则返回明确的管理接口错误，不伪造 0 占用。

## 验证

- Repository 单元测试：训练与调试均入表、终态被排除、用户名回退正确。
- API 集成测试：SuperAdmin 全平台、TenantAdmin 本团队、Engineer 403。
- 前端单元测试：分类统计、持续时间和字段归一化。
- 前端构建、Go 全量测试以及生产只读接口验收。
