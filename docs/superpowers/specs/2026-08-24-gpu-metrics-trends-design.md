# GPU 实时指标与趋势面板设计

## 目标

修正 GPU 页面把低频瞬时采样误解为实时状态的问题，并提供适合训练运维的历史曲线。整个改造只读取 Prometheus/DCGM 并滚动更新平台前后端，不修改 RayJob、RayCluster、训练 Pod 或 VKE 托管的 DCGM DaemonSet。

## 指标语义

- 当前卡片同时展示最新采样、近 1 分钟平均和采样时间；超过 90 秒没有新样本时标记为“数据延迟”，不能把缺失数据渲染成 0。
- 趋势支持 15 分钟、1 小时、6 小时、24 小时和 7 天。服务端为每个范围选择固定步长，限制返回点数。
- 利用率曲线使用时间窗口平均值以消除 30 秒 DCGM 采样与训练数据加载周期之间的混叠；原始最新值仍保留在卡片中。
- 显存展示 GiB 与百分比，功率展示单卡功率与节点合计，温度展示单卡值及节点最高值。

## 后端

新增受控的 GPU 历史查询接口。调用者只能选择预定义时间范围和节点，不能提交任意 PromQL。后端使用 Prometheus `query_range` 查询 GPU 利用率、显存使用量、温度和功率，按 GPU UUID 合并，并返回设备身份、工作负载标签、采样时间和时间序列。

当前指标接口补充样本时间、Pod、Namespace 和容器归属。Prometheus 不可用或单项序列缺失时返回明确错误或空序列，不伪造 0。

## 前端

- 资源池总览显示总卡数、正在计算、调度占用、近 1 分钟平均利用率、总显存和总功率。
- 趋势区先选节点，再并排展示利用率、显存、功率和温度四张曲线；每条线对应一张 GPU，悬停显示时间与准确值。
- 节点卡片显示 8 卡负载均衡、节点平均利用率、显存占比、总功率及异常提示。
- 单卡卡片显示最新值、1 分钟平均、显存进度、温度、功率、归属任务 Pod 和数据新鲜度。
- 缺失采样显示曲线断点；卡间利用率长期差异、显存超过 90%、温度过高或已分配但长期空闲时显示告警，而不是自动修改训练。

## 验证与发布

- Go 单元测试覆盖 Prometheus 时间戳、标签保留、固定时间范围、GPU 序列按 UUID 合并和非法参数拒绝。
- 前端单元测试覆盖窗口、数据新鲜度、节点聚合、负载不均和曲线变换。
- 前端构建与 Go 全量测试通过后，仅滚动升级 backend/frontend Deployment。
- 发布前后记录运行中 RayJob UID、状态及训练 Pod UID，确认没有重建或中断。
