# 命令行上手、客户端升级与团队退役

状态：本地实现与开发验证已完成，尚未发布上线；本文件不是生产验收记录。

## 范围与顺序

用户确认不做命令生成器，两种提交方法放入 UI 使用说明。拆成三个可独立验证的子项目：

1. UI 命令说明与 spk-rayjob 版本提示、主动升级。
2. 新节点接入说明和缓存注册脚本修正。
3. 仅超级管理员可执行的团队退役。

不占用 GPU，不提交验证训练，不实际退役 test 团队，不删除 Namespace、PVC、原始数据或历史任务。本次开发不代表授权生产部署。多机 GPU/NCCL、吞吐和故障恢复验收继续等待资源可用。

## A. CLI 上手与升级

### 用户体验

- UI 使用说明分别给出首次安装、登录、登记镜像选择、代码目录、提交、排队判断、日志、取消和恢复；Linux/macOS/Windows 明确各自语法。
- 保留 spk-rayjob 和 Ray 原生提交两个入口，不增加表单驱动命令生成器。
- 说明 Ray 原生命令连接平台 `/ray` 网关，不直连某个训练集群。PAT 不出现在命令参数、输出或永久示例中。
- 给出普通挂载与 Ray Train streaming 两组完整示例，明确数据版本、可选场地、资源、队列、输出路径、两种任务 ID 的区别。
- 客户端兼容版本和训练镜像 Ray 版本分别说明，不把现有 Ray CLI 2.35 协议兼容基线未经验证就替换为 2.58。

### 版本契约

- 下载服务提供与实际 CLI 制品一起发布的机器可读版本清单，包含最新版本、最低兼容版本、更新说明及支持的平台制品 SHA256 和大小。
- 清单随 CLI 制品发布，而不是随每次 backend/frontend 发布改变。最低兼容版本只有明确兼容性变更才提高。
- 用受校验的结构化发布序号比较 release-日期-序号版本，不做字符串字典序比较；未知/dev 构建提示版本无法比较，不伪造“过旧”结论。
- 登录成功后检查更新；submit 在打包/上传前检查。普通新版只向 stderr 提示，不破坏 JSON stdout；检查设置短超时，不影响日志/取消等操作。
- 清单不可达时不因“有新版”阻断原本兼容的提交，也不声称客户端已是最新。最低兼容约束由平台兼容闸门负责，不能只依赖客户端自觉。
- 提交请求带 CLI 版本/协议标识。兼容拒绝发生在创建任务前，给出可操作错误与升级方式；不得把 Ray 原生请求误判成旧 spk 客户端。旧客户端缺少新标识的处理须保留现有路径，不能凭缺少字段强制封禁全部用户。
- UI 下载页展示最新版本、最低兼容版本、更新内容、升级命令与未知/加载失败状态。

### 主动升级

- 新增 `spk-rayjob upgrade`，不自动执行升级，不后台覆盖可执行文件。
- 从用户已配置的平台 HTTPS 地址下载清单与匹配 OS/arch 的制品；不接受清单指定的任意外站 URL，不向下载请求发送登录凭据，不允许 HTTPS 降级。
- 限制元数据与二进制大小、超时和重定向；校验 SHA256 和制品身份后才允许替换。
- 同目录临时文件、正确执行权限、原子替换；校验失败、无写权限、磁盘满或下载中断均保留旧程序。锁定升级操作防止并发替换。
- Windows 使用退出后替换方案，并保留可恢复旧文件；不能用 Linux 重命名行为假定正在运行的 Windows exe 可覆盖。
- 明确不支持的系统/架构，不能下载“最接近”的制品。首次范围沿用现有 Linux amd64、macOS arm64、Windows amd64。
- 不修改用户 shell 配置，不默认 sudo，不安装到与当前运行程序无关的位置。

### 首次迁移边界

现有旧 CLI 没有版本检查和 upgrade 命令，不能在服务器更新后自动获得这些能力。首次上线必须在 UI 提示用户从外部提交页重新下载一次；升级到新客户端以后才具备自动提示和主动升级命令。服务器不能替用户远程替换本地程序。

### 文档持久化

UI 文档已经可由超级管理员编辑，后台 seed 不能粗暴覆盖线上编辑。内置文档新增只补缺失项；既有文档升级使用版本冲突保护，发现人工修改则保留原文并提供待审更新，不静默覆盖。部署验收必须确认 UI 实际发布内容，不只看源码中的 Markdown。

### 验收

先写失败测试：版本比较、可选/必须更新、旧客户端迁移、离线、超时、错误平台、未知版本、checksum 错误、重定向、无权限、替换失败和并发升级。两种完整命令做 shell/PowerShell 合约测试；不执行用户训练命令。Linux/macOS/Windows 更新流程不能仅用交叉编译宣称全部运行验收通过。

## B. 新节点接入

### 既有问题

`OPERATIONS_GUIDE.md` 的“NVMe 未来使用”描述过时；`register-node.sh` 依赖 production 标签且生成硬编码旧节点列表，不能作为安全扩容补丁直接应用。

### 修改方案

- 文档将加入 VKE/Kubernetes 与加入平台 GPU 资源池分开；云节点与机房节点按集群实际方式接入，不编造 join token 或 kubeadm 命令。
- 新节点保持 cordon：Node/CNI/containerd、GPU 驱动/device plugin/DCGM、DNS、镜像拉取、FSX/NFS、节点网络和双盘验收后，才准备放行。
- 标签与可调度状态分开说明。注册期间可以在 cordon 状态设置对应池标签，最终由管理员解除 cordon。
- 脚本不再内置旧节点清单；读取明确的现有 data1/data2 配置，分别合并新节点对应单盘目录，保留所有既有节点，输出两份 review-only 补丁和报告。
- 拒绝同名冲突、路径错误、符号链接、不真实挂载、输出覆盖及混用双盘列表；不格式化、不自动改 Helm、不自动 uncordon。
- 4090 标签只用于对应硬件池，异构节点单独确认资源池与镜像兼容性。
- 文档解释物理容量发现、Kueue 配额同步、团队配额和任务规模上限是不同层；加入新节点不会改变正在运行任务的固定 worker 数。

### 验收

使用 mock kubectl/ssh 测试第三、第四节点加入、多次登记、保留旧列表、两个单盘映射、cordon 检查、检查失败不输出可应用补丁。真实新节点验收需有明确节点目标后执行。

## C. 团队退役

### 状态与权限

- 使用持久 `ACTIVE` / `RETIRED` 生命周期，记录退役时间和操作者；保留团队 ID，不能重新创建同 ID 的团队。
- 仅交互式登录的 SuperAdmin 可预检和退役。TenantAdmin、普通用户和 PAT 不得执行；禁止退役当前管理员所在团队及平台 bootstrap 管理团队。
- 默认团队列表隐藏已退役项；超级管理员可切换查看其历史与审计。本期不提供恢复、物理删除或成员自动迁移。

### 预检与执行

- 先只读展示依赖数量与阻断原因：运行/排队训练、活动工作区、发布任务、上传/传输、成员与会话、历史训练、数据集、镜像、挂载与存储引用。
- 有活动工作即阻止退役；状态不明或 Kubernetes 无法核实时失败关闭。历史记录和现有数据允许保留，不要求为了退役先删除训练历史。
- 页面明确“退役禁止该团队继续使用，不释放存储”，要求输入团队 ID 二次确认。
- 执行时重新预检并锁定团队状态，防止预检之后新提交穿透。同步撤销该团队 PAT/本地会话；OIDC 和已有令牌每次请求也必须检查团队状态。
- `EnsureIdentity` 当前会自动 upsert 团队，必须调整为尊重退役状态，禁止登录或旧请求把团队恢复。
- 所有团队写入入口与退役使用一致的状态门禁，包括 CLI/原生/UI 提交、用户创建、数据上传、镜像登记、工作区与发布；不能只隐藏前端按钮。
- 保留历史任务、成员记录、存储和命名空间，不启动后台物理清理。SuperAdmin 仍可审计历史，退役团队旧成员不能继续获取新访问凭据或发起新操作。
- 不远程杀死当前训练；如存在活动工作，管理员应等待结束后再退役。

### test 团队适用性

只读盘点发现 test 有35条历史训练、1个本地用户以及9个PVC，当前无运行或排队训练。该团队适合在用户单独确认后执行“保留历史与数据的退役”，不适合默认级联物理删除。本次实现不直接操作它。

### 验收

先写失败测试：越权、保护团队、活动任务拦截、历史保留、凭据失效、OIDC复活防护、重复退役、并发提交/上传、状态检查失败及审计。新增迁移按连续编号添加并更新版本测试；真实 PostgreSQL 事务/锁验证与本地 API/UI 验收均需完成。

## 取舍与后续发布

选择主动升级而非静默自动更新，避免未知时刻更换程序；选择团队退役而非级联删除，保留历史和存储；选择完善现有说明而非新命令生成器，遵守用户范围。

实现完成后分别报告代码、测试、未验证平台和部署状态。未完成真实 Windows 更新或多机 GPU 验收时必须明确说明。上线按 release skill 最小覆盖与 dry-run，CLI 制品与版本清单一起发布，任何团队或节点操作另行确认。
