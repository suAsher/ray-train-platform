# 独立模型评估与数据版本实施计划

**目标：** 用户从实验中心的共享模型版本发起独立评估，选择具体的数据版本和验证集/测试集，通过不可变评估方案执行，查看真实报告并比较同口径结果。保留 11 个一级菜单；本阶段不包含审批或推理服务。

**基线：** 后端四端 `4fd302153e57a6ab48c1d0158cf0e6d3769427a1`；线上 backend `release-20260912-10-77c10a0`、Helm 221、schema 49；Portal dev `c2f9b48ce2e936e1b3edd6826f16dc2b8c1b8726`。发布前重新核对，不能覆盖并发更新。

## 用户流程与数据边界

1. 实验中心 → 模型 → READY 权重版本 → 发起评估。
2. 选择已登记的评估方案。方案固定允许的运行环境摘要、Git 完整提交、启动参数、数据格式和报告协议；不能假定任意权重文件可用同一个脚本加载。新代码产生新方案；历史方案仅可启停。
3. 选择自己有权使用的具体 READY 数据版本，明确选择 val 或 test；禁止 latest、失效时回退和空划分。第一版评估使用该划分的全部场地，暂不开放尚无可靠预检的场地子集。
4. 预检展示权重 SHA、数据 manifest、划分及样本数量、方案代码/镜像、资源需求；提交后进入现有配额、排队和 RayJob 调度。
5. 评估记录展示执行状态及报告有效性。任务成功退出且有效报告已写入才算评估完成；没有报告不视作成功。
6. PUBLIC 数据集的报告供登录成员查看；TEAM 数据集的报告保留团队访问边界。共享模型不改变源数据权限。权重和原训练文件均不改写。
7. 比较仅接受数据 manifest、划分、场地、评估方案和配置一致的有效成功结果；保留零值，指标单位/方向不一致时拒绝误导性比较。

数据集继续保留在“版本化数据集”，增加 train/val/test 用途和样本数说明、固定版本深链、无可用版本提示。训练数据来源与独立评估数据来源分开显示。当前公开目录中一个数据集无发布版本；streaming v2 的 READY 版本为 train 15,228 / val 1,620 / test 0，这些数量仅是核查快照。

## 实现与并行职责

- [x] `backend/modelevaluation/`：不可变来源、输入和严格报告校验、配置摘要、状态与比较合同；先编写单元测试。
- [x] `backend/repositories/model_evaluation*.go`、migration 0050：方案、评估、审计；创建幂等、预留 Job ID、配额限制、报告不可变、任务终态收敛；真实 PostgreSQL 升级/重放/权限测试。
- [x] `backend/api/model_evaluation*.go`：方案与评估 API、固定来源预检、现有提交服务调用、取消、报告下载和比较；接口鉴权、限流和失败响应。
- [x] `SubmissionService`：仅内部评估来源可预留 Job ID，提交前复核镜像与数据摘要；继续由现有仓库事务执行 GPU 配额与 outbox，不绕过准入。
- [x] `main` / `k8s`：从可信评估记录注入运行参数；复用已有任务专属凭据，仅授权该评估权重下载与报告写入。公开 JobSpec 不能伪造内部字段；不向训练容器加入个人 PAT。
- [x] `examples/model-evaluation/`：随用户代码携带的轻量 Python 客户端示例，下载校验和报告协议；源码不进入训练镜像。
- [x] 独立 Portal dev：评估 tab、发起表单、方案详情、报告与比较、数据集说明和定位；保留既有模型/训练/MLflow API 功能。
- [x] 使用说明保留问题对应文档，补充外部 SDK/REST 与平台任务注入连接的区别，并增加评估、数据选择与失败排查内容。
