# 模型发布与推理服务实施计划

**目标：** 完成已经同意的第三阶段，使用户能从固定权重和有效评估申请发布、由其他授权成员审核、关联原生 MLflow Registry，并实际启动、调用、停止和回滚推理服务。

**架构：** 共享模型、独立评估保持既有权威记录；新增发布申请、审核、通道指针、Registry同步记录与服务部署历史。推理计算复用 SubmissionService、RayJob、Kueue 和现有团队配额。推理代码和权重经任务专属凭据内网分发，代码不进入训练镜像。

**基线：** 后端本地/GitHub/GitLab/构建机 main 为 `b11fcd2434d957ee1ec565b5b7ab235cc44b498b`；线上后端 release-20260912-12-3fb0b67，Helm223/schema50，两个副本健康。Portal独立dev为 `7ae0f768dd187877f4e8a812b6cc436717dbbfd4`。每次推送和部署前再次核对并发更新。

## 用户合同

- 模型目录及服务状态所有平台成员可见；所有者管理，管理员按平台角色操作。团队私有评估的报告不因共享目录泄露。
- 申请发布必须绑定同一版本的 SUCCEEDED/VALID 评估及报告SHA，不能以任务退出成功或权重READY代替评估结果。
- 审核需有权限的其他成员完成，申请人及模型所有者不能自审；理由、证据、时间和历史均保存。
- 发布与回滚只指向同一模型的已批准版本；原生MLflow全量接口仍保持现有权限。原生Registry可被用户修改，平台展示同步失败或不一致，不借上游别名自动绕过平台审批。
- 普通pth/safetensors是权重，不假定含推理代码。用户选择已登记的不可变推理契约，明确镜像、ZIP代码、启动参数、输入输出、8000端口的healthz和invocations。代码在内网下载，不在节点执行git clone。
- 服务创建经现有资源准入，状态区分排队、启动、就绪、停止、失败；就绪需实际健康响应，调用需实际HTTP结果。每次部署有明确到期时间，最长7天；持续占用配额必须可见。
- 停止只操作该服务绑定的任务。版本切换先回收旧实例再启动新实例，展示短暂不可用，不能承诺零停机；保留可回滚的部署历史。
- 实验中心保留11个一级菜单，在现有模型/评估旁增加推理服务。所有按钮调用真实接口；帮助保留独立问题文档，增加发布审核、Registry、服务接入和失败排查。

## 完成标准

评估成功报告、独立审核、Registry关联、服务健康、实际推理请求、停止释放资源、历史版本回滚均有证据；隔离协议验收与生产验收分别记录。合成样本验证平台协议，不代表业务模型精度。真实业务模型需其加载代码、数据适配和指标定义，不伪造业务结果。
