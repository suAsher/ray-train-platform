# 共享模型与用户自助管理实施计划

> 按 release skill 执行；测试、格式检查和构建只在构建机。各阶段分别验收，不能把设计或页面占位视为上线能力。

**Goal:** 用户从本人训练输出显式选择权重，生成所有登录用户可查看、下载和追溯的模型版本，自主管理说明与归档；逐阶段接入固定数据版本的独立评估、审批和推理服务。

**Architecture:** 平台共享目录保存模型及不可变版本来源，独立对象前缀保存经 SHA-256 校验的权重副本。现有个人文件、任务权限与原生 MLflow 协议不变。后续评估是独立任务，审批绑定不可变版本和报告，服务绑定获准版本。MLflow 原生 Registry 继续可用，平台目录不冒充已经注册到 MLflow 的模型。

**Tech Stack:** Go/Gin/GORM/PostgreSQL、TOS 分片对象、独立 Portal Vue 3/Element Plus、现有 Kueue/RayJob 准入。

## 阶段一：共享模型版本（本次先交付完整操作链）

- [x] `backend/modellifecycle/`：领域合同、输入验证、异步快照状态机与完整性校验。状态为 PENDING/COPYING/READY/FAILED；状态与版本评价/审批状态分离。
- [x] `backend/repositories/model_lifecycle.go` 与 migration 0049：模型、版本、操作记录；共享查询、所有者/管理员修改、乐观版本检查、复制租约、额度限制。
- [x] `backend/objectstore/model_snapshots.go`：仅服务端生成 ID 的独立不可变对象；8 MiB 分片、单文件上限20 GiB、流式计算文件和分片 SHA-256；不删除/改写源文件。
- [x] `backend/api/model_lifecycle*.go`：读共享目录/详情/下载；交互用户创建模型、从本人任务登记版本、编辑说明、归档/恢复。严格路径约束；仅允许明确权重格式；仅接受终态任务，避免读取仍在写入的权重。

### 第一阶段用户合同

实验中心保留训练记录、MLflow API，新增“模型”。所有登录成员均可看共享目录；“全部 / 我创建的”只是筛选。模型详情展示说明、创建者、版本列表、权重摘要、来源 Job/Run（如有）、代码摘要与数据版本（如有）。版本只有复制校验完成才可下载；归档是目录管理，不删除权重。管理按钮依赖服务器 canManage。未经真实验收的评估、审批、服务按钮不伪装成可执行能力。

## 阶段二：独立评估

- [x] 定义评估器注册合同：环境镜像、不可变代码、命令、输入/输出 schema、报告协议；不可假设任意 pth 都能运行。
- [x] 评估任务固定模型权重 SHA、READY 数据版本 manifest 与评估器版本，复用训练任务准入和资源配额，独立记录执行状态与报告有效性。
- [x] 报告协议支持由评估代码上报场地/类别/距离切片和原始指标；同一数据 manifest/协议才可比较。失败报告不变成通过。
- [ ] 通过专用获准模型和数据的实际运行验收。未获得具体生产计算授权时只完成隔离验证。

## 阶段三：审批发布与推理服务

- [ ] 模型版本中提交审批、授权审核者决定、记录原因与不可变评估证据；避免自行审批。
- [ ] 注册明确推理契约（框架、输入输出、加载代码和运行环境），从审批版本创建服务；服务就绪与真实请求验证独立于 Helm 成功。
- [ ] 授权操作者启停和版本回滚，保留部署历史；GPU 资源须进入现有资源治理。
