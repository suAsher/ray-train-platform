# MLflow external tracking API

This document describes the external experiment tracking API for integrations. The [release and validation record](MLFLOW_EXTERNAL_TRACKING_VALIDATION_20260912.md) separates deployed versions, isolated integration tests and outstanding production acceptance.

Use this API when another service needs to create a platform-owned external experiment/run, append metrics, parameters or tags, read a run summary, or finish that run. The platform database owns identity, team membership, resource ownership, idempotency and audit. MLflow stores the tracking payload and is not the authorization source.

## What to provide to an integrator

Provide only these values:

- API origin, for example the approved RayTrain HTTPS origin.
- A short-lived RayTrain personal access token delivered through a secret manager or environment variable, never in a URL, source file or log.
- PAT scopes: `experiments:read` for reads; `experiments:read` and `experiments:write` for create/log/finish.
- The platform external experiment ID after `POST /api/v1/mlflow/experiments` succeeds.
- The platform external run ID after `POST /api/v1/mlflow/experiments/{experimentId}/runs` succeeds.
- A stable `Idempotency-Key` for each create request. Reuse the same key for the same create request; use a different key for a different experiment or run.

Do not provide the internal MLflow tracking URL, MLflow database credentials, object-store credentials, browser cookies, internal artifact paths, upstream Kubernetes service names, or the MLflow UI proxy cookie.

## Identifiers

External tracking has two identifiers for each platform run:

- `id`: the RayTrain platform run ID. Use this in REST paths and in the SDK subset `run_id` field.
- `mlflowRunId`: the upstream MLflow run ID. It is returned for diagnostics and UI cross-checking. Do not use it as the REST path ID or SDK subset run ID.

Likewise, an experiment response contains `id` for the platform experiment and `mlflowExperimentId` for the upstream MLflow experiment. External runs are not training jobs. A training `job_id`, a platform external `run.id`, and an upstream `mlflowRunId` are different values.

## REST endpoints

All REST endpoints are under `/api/v1/mlflow` and return the normal platform envelope:

```json
{
  "success": true,
  "data": {},
  "request_id": "request id from the gateway or generated by the backend"
}
```

Errors use the same envelope shape with `success: false` and an `error` object.

### Capabilities

```bash
curl -sS \
  -H "Authorization: Bearer $RAYTRAIN_PAT" \
  "$RAYTRAIN_API/api/v1/mlflow/capabilities"
```

The capability payload reports the current scopes, limits and unsupported areas. `sdkCompatible` becomes true when the external tracking service and SDK routes are configured. Always check `sdkProtocol` (`tracking-subset`), `sdkClientVersion` (`3.14.0`), `sdkMethods` and `sdkRequiresPrecreatedRun`; it is not a full MLflow Tracking Server.

### Create an experiment

```bash
curl -sS \
  -X POST \
  -H "Authorization: Bearer $RAYTRAIN_PAT" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $EXPERIMENT_CREATE_KEY" \
  -d '{"name":"external-evaluation"}' \
  "$RAYTRAIN_API/api/v1/mlflow/experiments"
```

Request body:

```json
{"name":"external-evaluation"}
```

The name must be non-empty, trimmed, valid UTF-8, contain no control characters, and be at most 128 bytes. The same caller can retry the same request with the same `Idempotency-Key`. If the operation is still reconciling with MLflow, the API returns `409 MLFLOW_TRACKING_PENDING`; read/list before retrying and retry with the same key only for the same request.

### List experiments

```bash
curl -sS \
  -H "Authorization: Bearer $RAYTRAIN_PAT" \
  "$RAYTRAIN_API/api/v1/mlflow/experiments?limit=50"
```

`limit` defaults to 50 and is capped at 100. `nextCursor` is an opaque signed cursor bound to the caller, team and query. Do not edit or share it.

### Create a run

```bash
curl -sS \
  -X POST \
  -H "Authorization: Bearer $RAYTRAIN_PAT" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $RUN_CREATE_KEY" \
  -d '{"name":"candidate-run"}' \
  "$RAYTRAIN_API/api/v1/mlflow/experiments/$PLATFORM_EXPERIMENT_ID/runs"
```

The path uses the platform experiment ID. The response `id` is the platform run ID to use for later log/read/finish calls. Retry create only with the same idempotency key and the same request body.

### List runs in an experiment

```bash
curl -sS \
  -H "Authorization: Bearer $RAYTRAIN_PAT" \
  "$RAYTRAIN_API/api/v1/mlflow/experiments/$PLATFORM_EXPERIMENT_ID/runs?limit=50"
```

The result is paginated by platform-owned runs. It is not a full MLflow export.

### Get one run

```bash
curl -sS \
  -H "Authorization: Bearer $RAYTRAIN_PAT" \
  "$RAYTRAIN_API/api/v1/mlflow/runs/$PLATFORM_RUN_ID"
```

The response includes the platform run record plus latest metrics, params and bounded metric series. Current bounds are 20 metric keys and 500 points per key. This is enough for dashboards and comparisons, but not a complete metric history export.

### Log a batch

```bash
curl -sS \
  -X POST \
  -H "Authorization: Bearer $RAYTRAIN_PAT" \
  -H "Content-Type: application/json" \
  -d @batch.json \
  "$RAYTRAIN_API/api/v1/mlflow/runs/$PLATFORM_RUN_ID/log-batch"
```

`batch.json` may contain `metrics`, `params` and `tags`. At least one item is required. Each array is capped at 100 items; the JSON body limit is 256 KiB. Metric keys allow letters, digits, `.`, `_`, `-` and `/`. Parameter and tag values are bounded by the backend. Reserved keys and aliases such as `platform.*`, `mlflow.*`, `run_id`, `job_id`, `artifact_uri`, `status`, `start_time` and `end_time` are rejected.

MLflow batch writes are not transactional. If a request times out or returns `502`/`503`, some values may already be stored. Read the run before retrying; do not blindly retry with new timestamps or steps.

### Finish a run

```bash
curl -sS \
  -X POST \
  -H "Authorization: Bearer $RAYTRAIN_PAT" \
  -H "Content-Type: application/json" \
  -d '{"status":"FINISHED"}' \
  "$RAYTRAIN_API/api/v1/mlflow/runs/$PLATFORM_RUN_ID/finish"
```

Allowed terminal statuses are `FINISHED`, `FAILED` and `KILLED`. Finish is designed to be safe to repeat when the upstream run is already in the requested terminal status. If the API reports `PENDING` or `UNAVAILABLE`, read the run state before retrying.

## SDK subset

The SDK adapter is mounted at `/api/v1/mlflow-tracking/api/2.0/mlflow`. Set the MLflow tracking URI to the prefix without `/api/2.0/mlflow`:

```python
import os
import time
import mlflow

base = os.environ["RAYTRAIN_API"].rstrip("/")
client = mlflow.tracking.MlflowClient(
    tracking_uri=base + "/api/v1/mlflow-tracking"
)

platform_run_id = os.environ["RAYTRAIN_PLATFORM_RUN_ID"]
client.get_run(platform_run_id)
client.log_metric(platform_run_id, "external/quality_score", 0.91, step=1)
client.log_param(platform_run_id, "external.evaluator_version", "v1")
client.set_tag(platform_run_id, "external.source", "quality-service")
client.set_terminated(platform_run_id, status="FINISHED", end_time=int(time.time() * 1000))
```

Pass the PAT as the MLflow bearer token using the supported client environment, for example `MLFLOW_TRACKING_TOKEN` in the execution environment. The SDK subset accepts only a REST-precreated platform run ID. For `runs/update`, the adapter honors the SDK `end_time` field when supplied. It does not support `create_experiment`, `create_run`, `start_run`, autologging run creation, artifact upload, model logging, registry, traces or serving.

The SDK response deliberately returns `artifact_uri` as `raytrain-disabled:/<run-id>`. This prevents clients from inferring or writing internal artifact storage. Use platform artifact/model APIs added in later phases instead.

Registered SDK paths are limited to:

- `GET /api/v1/mlflow-tracking/api/2.0/mlflow/runs/get`
- `POST /api/v1/mlflow-tracking/api/2.0/mlflow/runs/log-batch`
- `POST /api/v1/mlflow-tracking/api/2.0/mlflow/runs/log-metric`
- `POST /api/v1/mlflow-tracking/api/2.0/mlflow/runs/log-parameter`
- `POST /api/v1/mlflow-tracking/api/2.0/mlflow/runs/set-tag`
- `POST /api/v1/mlflow-tracking/api/2.0/mlflow/runs/update`

All other MLflow protocol paths return 404 or an MLflow-style error.

## Unsupported in this phase

The current external tracking API supports Experiment Tracking only. The existing native MLflow UI path remains a shared administrative dashboard/proxy and is not the ownership-isolated external API described here. Do not use the raw UI path as evidence of platform Registry approval or external ownership isolation. Artifact Management, Model Registry, Model Evaluation, Model Serving and full MLflow UI/API compatibility are intentionally not part of this contract. Model package upload, registry approval, independent evaluation jobs and serving deployments need separate platform-owned resources and authorization before they can be exposed safely.
