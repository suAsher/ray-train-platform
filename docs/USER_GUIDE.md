# 用户使用手册

面向在平台上跑训练的算法工程师。管理员请看 [ADMIN_GUIDE.md](ADMIN_GUIDE.md)，部署运维请看 [BUILD_AND_DEPLOY.md](BUILD_AND_DEPLOY.md)。

---

## 1. 登录

浏览器打开平台地址，用管理员给你的账号登录。

平台支持两种登录方式，管理员会告诉你用哪种：

- **本地账号** —— 用户名 + 密码，直接登录
- **企业 SSO** —— 点「使用企业 SSO 登录」跳转到公司统一认证

登录后右上角显示你的用户名，中间显示你所属的**团队（租户）**。你只能看到本团队的任务、配额和数据，这是平台强制的隔离，不是界面过滤。

左下角常驻「我的 GPU 配额」，显示本团队已占用/总量。**这个数字和提交任务时的准入校验用的是同一份计算**，显示还剩 8 卡就一定能申请 8 卡。

## 2. 界面结构

登录后左侧有两组菜单，普通工程师只看得到「工作台」：

| 菜单 | 用途 |
|---|---|
| 我的训练任务 | 提交任务、看状态、看日志、停止任务 |
| 交互式调试 | 起一个带 GPU 的在线开发环境，用 JupyterLab 调代码 |
| 数据与模型产物 | 查看数据集与训练产物 |

「平台管理」组只有管理员可见。

## 3. 提交训练任务

### 3.1 从界面提交

「我的训练任务」→ 右上角 **+ 创建训练任务**。需要填的东西：

| 字段 | 说明 |
|---|---|
| 任务名称 | 小写字母、数字、短横线 |
| 训练镜像 | **从下拉里选**，带「（默认）」的是推荐环境 |
| 代码来源 | Git 仓库 + commit，或上传的代码包 |
| 启动命令 | 例如 `python train.py --config configs/sft.yaml` |
| Worker 数 / 每 Worker GPU 数 | 总卡数 = 两者相乘 |

提交后任务进入队列，你会在列表里看到它。

### 3.2 镜像怎么选

镜像决定了你的代码能 import 到什么。**镜像由管理员统一登记，都锁定了 sha256 digest**——同一个镜像今天和三个月后跑出来的环境完全一致，这是训练结果可复现的前提。

如果现有镜像缺你要的依赖，两个办法：

1. 让管理员构建一个新镜像并登记进目录（推荐，团队复用）
2. 在启动命令里 `pip install`（快，但每次任务都要装一遍，且不可复现）

### 3.3 代码从哪来

**Git 仓库**（最常用）：填仓库地址和 commit SHA。必须是**具体的 commit**，不能填分支名——分支会变，训练就不可复现了。

私有仓库需要管理员先在「租户与配额」页配好该 Git 主机的凭证，配好之后你正常填地址即可，平台会自动带上认证。

**代码包上传**：适合本地还没提交进 Git 的代码，见下面的命令行方式。

## 4. 任务状态怎么看

列表顶部四个计数是你最关心的：进行中 / 已成功 / 失败 / 占用 GPU。

状态含义：

| 状态 | 含义 | 通常要做什么 |
|---|---|---|
| 排队中 | 已提交，等待配额 | 等；如果一直排队，看是不是团队配额满了 |
| 启动中 | 正在拉镜像、拉代码、起 Ray 集群 | 等，首次拉镜像会慢 |
| 运行中 | 训练在跑 | 看日志 |
| 已成功 | 正常结束 | GPU 会自动释放 |
| 失败 | 训练报错或超时 | 看日志定位 |

**任务结束后 GPU 会自动回收**，不需要手动清理。

默认只显示「我提交的」，切到「全team」能看到同事的任务。

## 5. 交互式调试

「交互式调试」→ 选镜像 → **启动单卡 4090 调试环境**。

起来的是一个**真正的 Ray 集群**（一个 head + 一个带 GPU 的 worker），不是普通容器。所以你在 Notebook 里：

```python
import ray
ray.init()                      # 连的是真集群
print(ray.cluster_resources())  # 能看到 GPU
```

调试代码和训练代码用的是同一套 Ray API，调通之后直接提交训练即可。

就绪后点 **打开 JupyterLab**。

> 每人同时只能有一个调试环境，它会占用一张 GPU。**用完请点「停止工作区」**，否则会一直占着卡，同事和你自己的训练任务都得排队。

## 6. 命令行提交

平台内置了 **Ray Jobs API 兼容网关**，不需要装任何平台专用工具，标准 Ray CLI 直接用。

### 6.1 准备

```bash
pip install "ray[default]==2.35.0"
```

在 Portal 里签发一个个人访问令牌（PAT），然后：

```bash
export RAY_ADDRESS=http://<平台地址>/ray
export RAY_JOB_HEADERS='{"Authorization": "Bearer <你的PAT>"}'
```

### 6.2 提交

```bash
ray job submit --working-dir . -- python train.py
```

`--working-dir .` 会把当前目录打包上传，所以本地没提交进 Git 的代码也能直接跑。

### 6.3 查看与跟踪

```bash
ray job list && ray job logs <submission-id> --follow
```

> **当前限制**：命令行提交依赖对象存储保存上传的代码包，而集群里的对象存储凭证尚未配置好，`ray job submit --working-dir` 会返回 503。在凭证修好之前，请用 **Portal + Git 代码源** 提交，那条路不经过对象存储。网关本身已就绪（`ray job list`、版本握手都正常）。

## 7. 常见问题

**任务一直排队不动**
先看左下角配额是不是满了。如果配额有余量还在排队，多半是集群的 GPU 都被占用（包括别人的调试环境）。

**任务秒失败**
看日志。最常见的是镜像里没有你 import 的包——换一个带该依赖的镜像，或让管理员登记新镜像。

**提示镜像不在允许列表**
你填的镜像不在管理员登记的目录里。从下拉中选，或让管理员登记。

**私有仓库拉不下来**
让管理员在「租户与配额」页为该 Git 主机添加凭证。凭证按主机匹配，配一次全团队可用。

**调试环境起不来 / 一直在启动中**
GPU 可能被占满了。集群只有有限张卡，训练任务和调试环境共享。

**能看到别人的任务吗**
能看到同团队的（切到「全team」），看不到其他团队的。日志、数据、配额都按团队隔离。

## 8. 使用建议

- **代码用 Git + 固定 commit 提交**，别用分支名，否则出了问题无法复现
- **调试环境用完就停**，它独占一张 GPU
- **依赖尽量固化进镜像**，而不是每次任务 `pip install`——后者慢且不可复现
- **Checkpoint 写到对象存储或共享存储**，不要写容器本地目录，任务结束就没了
- **先用 1 卡跑通再放大**，多机训练的通信开销和单机不是一回事
